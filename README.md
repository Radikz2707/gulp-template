# 🚀 Gulp + TypeScript Professional Template (v2.1)

Современный, быстрый и полностью автоматизированный шаблон для профессиональной верстки. Построен на компонентном подходе (BEM) с использованием Gulp 5, Webpack 5 и **TypeScript**.

---

## 🚀 Быстрый старт (Развертывание нового проекта)

Чтобы начать новый проект на основе этого шаблона, выполните следующие команды в терминале:

1. **Клонируйте шаблон** в новую папку (точка в конце важна):
   ```bash
   git clone git@github.com:Radikz2707/gulp-template.git .
   ```
2. **Удалите связь с репозиторием шаблона**:
   ```bash
   rm -rf .git
   ```
3. **Установите зависимости** через стабильное зеркало (peer-зависимости будут разрешены автоматически):
   ```bash
   npm install --registry=https://npmmirror.com --legacy-peer-deps
   ```
4. **Инициализируйте структуру** и запустите сервер:
   ```bash
   npx gulp init && npm run dev
   ```

## 🛠 Команды проекта


| Команда | Описание |
| :--- | :--- |
| `npm run dev` | **Запуск разработки:** очистка `dist`, мгновенная компиляция базы и старт сервера за 1.5 сек. |
| `npm run build` | **Финальный билд:** глубокий линтинг, сжатие, вырезка лишнего CSS и генерация ZIP-архива с локальной датой. |
| `npm run lint` | **Контроль качества:** ручная проверка всех **TS**, SCSS и HTML файлов проекта на ошибки. |
| `npm run clean` | **Очистка:** полное удаление папки `dist` перед новой сборкой ресурсов. |
| `gulp init` | **Инициализация:** создает базовую модульную структуру Header-Main-Footer на TypeScript. |
| `gulp create --имя` | **Конструктор блока:** генерирует HTML/SCSS/**TS**/IMG в `src/components/` (Пример: `gulp create --hero`). |
| `gulp module --имя` | **Конструктор модуля:** создает новый **TS**/SCSS скрипт в `src/js/modules/` для кастомной логики. |
| `gulp remove --имя` | **Универсальный деструктор:** удаляет папку (блок/модуль) и полностью вырезает его из точек входа. |

## 🏗 Автоматизация и BEM

Шаблон реализует полный цикл управления независимыми модулями:

- **Авто-подключение**: При создании блока или модуля он автоматически регистрируется в `src/index.html`, `src/js/app.ts` и `src/scss/style.scss` в своем строго отведенном смысловом блоке.
- **Умное удаление**: Команда `remove` сканирует папки `components`, `modules` и `plugins`. Системные директории (библиотеки, шрифты) защищены от случайного удаления.
- **TypeScript Aliases**: Настроены встроенные алиасы `@/` (для корневой папки `src/js`), `@comp` (для `src/components`) и `@modules` (для `src/js/modules`) для чистых импортов без бесконечных цепочек `../../`.

## ⚙️ Особенности и технологии

### 💎 Качество кода
- **TypeScript**: Полная поддержка компиляции, строгая проверка типов (`strict: true`) и изоляция модулей для работы с Webpack.
- **Линтинг на лету**: ESLint (с поддержкой TS) и Stylelint интегрированы в вотчеры — проверка измененного файла происходит за доли секунды прямо при сохранении.
- **Prettier**: Автоматическое форматирование кода в едином стиле.
- **Sass @use**: Современная модульная система стилей без использования устаревшего и хрупкого `@import`.

### 🖼 Работа с графикой
- **Smart WebP Cache**: Автоматическая генерация WebP. Плагин `newer` сопоставляет базовые имена файлов, благодаря чему при запуске сервера картинки не пережимаются заново.
- **SVG Спрайты**: Умная очистка иконок через `cheerio` перед сборкой в спрайт (сохраняет `fill="none"` для корректного управления цветом из CSS).
- **PWA Favicons**: Автоматическая генерация полного адаптивного набора иконок и манифестов для всех типов устройств из одного файла `favicon.png`.

## 🛠 Архитектура и конфигурация

Управление всей сборкой осуществляется из единой точки — файла `gulp.config.js`. Его структура разделена на изолированные логические блоки:

### 1. Переменные окружения
В самом верху задаются базовые константы папок проекта. Изменение этих строк автоматически перестраивает всю карту путей сборщика:
* `preprocessor` — выбор используемого препроцессора стилей (`scss`, `sass`, `less`).
* `srcFolder` — папка с исходным кодом проекта (`src`).
* `buildFolder` — папка, в которую компилируется готовый результат (`dist`).

### 2. Блок `structure` (Кроссплатформенность)
Отвечает за пути, которые использует **конструктор компонентов** (`create`/`remove`/`module`). Все пути в этом блоке собираются через системный метод Node.js `path.join()`. Это гарантирует, что папки будут создаваться и удаляться корректно на любой операционной системе (Windows, macOS, Linux), защищая от багов экранирования слэшей.

### 3. Блок `paths` (Потоки Gulp)
Определяет точные направления для чтения и выгрузки файлов внутри тасков. Пути к исходникам (`src`) используют стандартные glob-маски (например, `**/*`), которые зафиксированы в виде классических POSIX-строк со слэшем `/`. Это критически важно, так как утилиты `gulp.src()` и `gulp.dest()` требуют именно такой формат для корректного поиска файлов по маске.

### 4. Блок `settings` (Оптимизация)
Централизованные настройки для используемых плагинов сжатия и линтинга:
* `webpQuality` — степень сжатия и качество генерируемых изображений `.webp` (по умолчанию `70`).
* `imagemin` — конфигурация плотности сжатия для классической графики (`jpeg: 75` качество и `png: 5` уровень оптимизации).
* `autoprefixer` — глубина поддержки старых версий браузеров (по умолчанию `last 10 versions`), передаваемая в плагин `PostCSS`.

## 📦 Работа со сторонними плагинами (Библиотеками)

В шаблоне реализован современный подход к разделению и управлению зависимостями. Избегайте ручного копирования файлов в проект — используйте системные методы:

### 1. Стандартные плагины (из репозитория NPM)
Все популярные библиотеки (например, `swiper`, `just-validate`, `inputmask`, `aos`) **не нужно скачивать вручную**. Они устанавливаются одной командой через терминал:
```bash
npm install swiper just-validate --registry=https://npmmirror.com --legacy-peer-deps
```
После установки Webpack и Gulp сами заберут их из папки `node_modules`. Подключение в коде выполняется следующим образом:

* **В скриптах (`src/js/app.ts`)**:
  ```typescript
  import Swiper from 'swiper';
  import { Navigation } from 'swiper/modules';
  
  // Инициализация внутри DOMContentLoaded
  ```
* **В стилях (`src/scss/style.scss`)**:
  ```scss
  @import 'swiper/css';
  @import 'swiper/css/navigation';
  ```

### 2. Кастомные или редкие плагины (Локальные)
Если библиотеки нет в NPM (например, специфический скрипт эквайринга от банка, старый скрипт без поддержки ES-модулей или ваш самописный плагин), для этого предназначена защищенная папка **`src/js/plugins/`**:

1. Положите файл плагина по пути: `src/js/plugins/my-custom-plugin.js`.
2. Импортируйте его в `src/js/app.ts`, используя настроенный TypeScript-алиас **`@plugins`**:
  ```typescript
  import { initCustomFeature } from '@plugins/my-custom-plugin.js';
  
  initCustomFeature();
  ```

## 📝 Важные примечания
1. **Точка входа**: Главный файл выполнения скриптов — `src/js/app.ts`. При импорте фронтенд-компонентов в этот файл расширения `.ts` или `.js` указывать не нужно благодаря настроенному резолюшну Webpack.
2. **Шрифты**: Исходные файлы (`.ttf` / `.otf`) добавляйте в `src/fonts/src/`. Сборщик автоматически конвертирует их в облегченный формат `.woff2` и сгенерирует файл подключения `_fonts.scss`.
3. **Иконки для спрайта**: Кладите векторные иконки в `src/images/src/`. Файл `sprite.svg` соберется в корне папки назначения, а вызов в HTML осуществляется через `<svg><use href="images/sprite.svg#имя-файла"></use></svg>`.
