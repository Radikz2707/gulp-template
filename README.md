# 🚀 Gulp + TypeScript Professional Template (v2.1)

Современный, быстрый и полностью автоматизированный шаблон для профессиональной верстки. Построен на компонентном подходе (BEM) с использованием Gulp 5, Webpack 5 и **TypeScript**.

---

## 🚀 Быстрый старт (Развертывание нового проекта)

Чтобы начать новый проект на основе этого шаблона, выполните следующие команды в терминале:

1. **Клонируйте шаблон** в новую папку (точка в конце важна):
   ```bash
   git clone git@github.com:Radikz2707/gulp-template.git .
   ```
2. **Удалите связь с репозиторием шаблона**:
   ```bash
   rm -rf .git
   ```
3. **Установите зависимости** через стабильное зеркало (peer-зависимости будут разрешены автоматически):
   ```bash
   npm install --registry=https://registry.npmmirror.com --legacy-peer-deps
   ```
4. **Инициализируйте структуру** и запустите сервер:
   ```bash
   npx gulp init && npm run dev
   ```

## 🛠 Команды проекта


| Команда | Описание |
| :--- | :--- |
| `npm run dev` | **Запуск разработки:** очистка `dist`, мгновенная компиляция базы и старт сервера за 1.5 сек. |
| `npm run build` | **Финальный билд:** глубокий линтинг, сжатие, вырезка лишнего CSS и генерация ZIP-архива. |
| `npm run lint` | **Контроль качества:** ручная проверка всех **TS**, SCSS и HTML файлов проекта на ошибки. |
| `npm run clean` | **Очистка:** полное удаление папки `dist` перед новой сборкой資源. |
| `gulp init` | **Инициализация:** создает базовую модульную структуру Header-Main-Footer на TypeScript. |
| `gulp create --имя` | **Конструктор блока:** генерирует HTML/SCSS/**TS**/IMG в `src/components/` (Пример: `gulp create --hero`). |
| `gulp module --имя` | **Конструктор модуля:** создает новый **TS**/SCSS скрипт в `src/js/modules/` для кастомной логики. |
| `gulp remove --имя` | **Универсальный деструктор:** удаляет папку (блок/модуль) и полностью вырезает его из точек входа. |

## 🏗 Автоматизация и BEM

Шаблон реализует полный цикл управления независимыми модулями:

- **Авто-подключение**: При создании блока или модуля он автоматически регистрируется в `src/index.html`, `src/js/app.ts` и `src/scss/style.scss` в своем строго отведенном смысловом блоке.
- **Умное удаление**: Команда `remove` сканирует папки `components`, `modules` и `plugins`. Системные директории (библиотеки, шрифты) защищены от случайного удаления.
- **TypeScript Aliases**: Настроены встроенные алиасы `@/` (для корневой папки `src/js`), `@comp` (для `src/components`) и `@modules` (для `src/js/modules`) для чистых импортов без бесконечных цепочек `../../`.

## ⚙️ Особенности и технологии

### 💎 Качество кода
- **TypeScript**: Полная поддержка компиляции, строгая проверка типов (`strict: true`) и изоляция модулей для работы с Webpack.
- **Линтинг на лету**: ESLint (с поддержкой TS) и Stylelint интегрированы в вотчеры — проверка измененного файла происходит за доли секунды прямо при сохранении.
- **Prettier**: Автоматическое форматирование кода в едином стиле.
- **Sass @use**: Современная модульная система стилей без использования устаревшего и хрупкого `@import`.

### 🖼 Работа с графикой
- **Smart WebP Cache**: Автоматическая генерация WebP. Плагин `newer` сопоставляет базовые имена файлов, благодаря чему при запуске сервера картинки не пережимаются заново.
- **SVG Спрайты**: Умная очистка иконок через `cheerio` перед сборкой в спрайт (сохраняет `fill="none"` для корректного управления цветом из CSS).
- **PWA Favicons**: Автоматическая генерация полного адаптивного набора иконок и манифестов для всех типов устройств из одного файла `favicon.png`.

## 📝 Важные примечания
1. **Точка входа**: Главный файл выполнения скриптов — `src/js/app.ts`. При импорте фронтенд-компонентов в этот файл расширения `.ts` или `.js` указывать не нужно.
2. **Шрифты**: Исходные файлы (`.ttf` / `.otf`) добавляйте в `src/fonts/src/`. Сборщик автоматически конвертирует их в облегченный формат `.woff2` и сгенерирует файл подключения `_fonts.scss`.
3. **Иконки для спрайта**: Кладите векторные иконки в `src/images/src/`. Файл `sprite.svg` соберется в корне папки назначения, а вызов в HTML осуществляется через `<svg><use href="images/sprite.svg#имя-файла"></use></svg>`.
